## Что это такое?

Простая нативная утилита для macOS, которая живёт в строке меню и позволяет одним кликом или шорткатом сразу сделать скриншот, сохранить его на диск и скопировать в буфер обмена.

> 🚀 **Личный Daily Driver:** \
> Пользуюсь этим инструментом каждый день уже больше полугода — он стал моим основным способом делать скриншоты на Mac.

## Зачем нужен этот проект

Стандартные сочетания macOS (`⌘⇧3` / `⌘⇧4`) заставляют выбирать: либо сохранить скриншот на рабочий стол, либо (с зажатым `Ctrl`) скопировать его в буфер. Сделать и то, и другое сразу система не умеет. В итоге тратишь время: или ищешь свежий файл в Finder, или вручную копируешь скриншот, чтобы отправить его в чат, письмо или тикет.

Сторонние утилиты вроде CleanShot X, Shottr или Monosnap предлагают кучу функций: редакторы, облачный шеринг, OCR. Но они висят в фоне, едят память, собирают телеметрию и часто требуют платной подписки.

SimpleScreen решает одну задачу и делает это чисто: режим **Save & Copy** (он включён по умолчанию) сразу сохраняет снимок в заданную папку и кладёт его в буфер — без лишних движений.

Ещё проект стал хорошей площадкой, чтобы глубже разобраться в системном уровне macOS (Darwin/UNIX):
- Работа с ядром и графическим сервером: ScreenCaptureKit, CoreGraphics, Carbon Event Manager.
- Отказоустойчивость дискового ввода‑вывода: атомарные операции, защита от конфликтов имён файлов и race conditions, автоматический переход на `~/Desktop`, если целевая папка недоступна.
- Наблюдаемость (Observability): вместо самописных логов в `/tmp` — нативная система Unified Logging (`os.Logger`) с разделением по категориям и настройками приватности.

### Сравнение: Системный скриншотер vs Сторонние утилиты vs SimpleScreen

| Критерий | Системный скриншотер macOS | Сторонние утилиты (CleanShot X и др.) | SimpleScreen |
| :--- | :--- | :--- | :--- |
| **Одновременный Save & Copy** | Нет (только или/или) | Да | **Да (в 1 клик или шорткат)** |
| **Потребление RAM в фоне** | Встроен в WindowServer | ~80–200 МБ | **~15–25 МБ** |
| **Сетевая активность и приватность** | Системные службы Apple | Фоновые запросы, аккаунты, облака | **0 сетевых вызовов (100 % Offline)** |
| **Сложность интерфейса** | Минимальная, но без гибкости | Перегруженный UI, сторонние оверлеи | **Минималистичный Menu Bar агент** |
| **Стоимость и лицензия** | Встроено в ОС | Платная лицензия / подписка | **Free Open-Source (Личный проект)** |

## Стек технологий

- **Ядро и интерфейс:** Swift 6 (с изоляцией на `MainActor`), AppKit, SwiftUI (окно настроек PreferencesView).
- **Системные API и фреймворки macOS:**
  - `ScreenCaptureKit` — захват экрана на уровне GPU/композитора: без задержек и артефактов.
  - `Carbon Events` — регистрация глобальных горячих клавиш через `RegisterEventHotKey`.
  - `ServiceManagement` (`SMAppService`) — нативный автозапуск при входе в систему без старых launchd‑скриптов.
  - `UserNotifications` — асинхронные системные уведомления с уникальными UUID.
  - `os.Logger` — структурированное логирование в macOS Unified Logging (subsystem `com.simplescreenapp.SimpleScreen`).
- **Сборка и дистрибуция:** Xcode 16+, `xcodebuild` CLI, локальная ad‑hoc подпись (`Sign to Run Locally`).

## Быстрый запуск

### Требования

- macOS 15.0+;
- Xcode 16+ (если собираете из исходников).

### Сборка и установка

1. **Клонируйте репозиторий и соберите Release‑версию через CLI:**
   ```bash
   git clone https://github.com/lenyldes/SimpleScreen.git
   cd SimpleScreen
   xcodebuild -project SimpleScreen.xcodeproj -scheme SimpleScreen -configuration Release build
   ```

2. **Установите приложение:**
   - Скопируйте собранный бинарник `SimpleScreen.app` из каталога `DerivedData/.../Build/Products/Release/` в `/Applications`:
   ```bash
   cp -R ~/Library/Developer/Xcode/DerivedData/SimpleScreen-*/Build/Products/Release/SimpleScreen.app /Applications/
   ```

3. **Первый запуск и права доступа (TCC):**
   - Из‑за локальной ad‑hoc подписи при первом запуске нужно обойти Gatekeeper: нажмите правой кнопкой на `SimpleScreen.app` в `/Applications` → **Open** и подтвердите запуск (это делается один раз).
   - Дайте разрешение на запись экрана: **System Settings → Privacy & Security → Screen Recording**. Приложение подхватит права сразу — перезапуск не нужен.

## Ключевые инженерные решения

1. **Двухуровневая отказоустойчивость дискового I/O (Graceful Degradation):**  
   - **Атомарная запись:** Используем `data.write(to: url, options: .atomic)` — так скриншот не повредится, если процесс прервётся или пропадёт питание.
   - **Защита от перезаписи при коллизиях:** Алгоритм `nonCollidingURL` проверяет, занято ли имя файла, и если за одну секунду делается несколько скриншотов, добавляет суффикс `Screenshot ... 2.png`.
   - **Резервный путь сохранения (Fallback):** Если целевая папка недоступна (например, диск отмонтирован), `CaptureEngine` не падает, а тихо сохраняет снимок в `~/Desktop` и показывает уведомление. При этом в буфер обмена изображение попадает в любом случае.

2. **Паттерн Probe-then-Swap при перерегистрации системных прерываний:**  
   - Когда пользователь меняет хоткей в `PreferencesView`, мы не удаляем старую комбинацию сразу. Сначала регистрируем тестовый шорткат с временным ID (`probeID = id + 1000`).
   - Если Carbon возвращает ошибку `eventHotKeyExistsErr` (конфликт с системной комбинацией), текущий хоткей остаётся рабочим, а интерфейс сразу показывает проблему.
   - Только если новая комбинация свободна, старый хоткей атомарно заменяется на новый — так не бывает ситуации, когда хоткей перестаёт работать.

3. **Интеграция с macOS Unified Logging System (SRE‑наблюдаемость):**  
   - Никаких самописных текстовых логов в `/tmp`: это экономит место и не оставляет открытых файловых дескрипторов при работе 24/7.
   - Используем нативный `os.Logger` с подсистемой `com.simplescreenapp.SimpleScreen` и категориями (`capture`, `areaSelect`, `hotkeys`, `launchAtLogin`).
   - Ротация, сжатие и управление памятью — на стороне подсистемы логирования macOS Darwin.

4. **Изоляция состояния фонового процесса и защита от race conditions:**  
   - Приложение работает как лёгкий фоновый процесс без иконки в Dock (`LSUIElement = true`, activation policy `.accessory`).
   - Все операции и доступ к общему состоянию `AppSettings` изолированы на `MainActor` по стандартам Swift Concurrency.
   - Логический барьер `isCapturing` не даёт запустить новый захват, пока не завершится текущий цикл ввода‑вывода.

## Практика разработки / особенности процесса

- **Глубокий FMEA‑аудит надёжности (26 граничных сценариев):**  
  Перед выпуском v0.2 мы прошли структурированный аудит сценариев непрерывной работы 24/7 и закрыли 26 потенциальных проблем, в том числе:
  - предотвращение двойного освобождения памяти и крашей окон `CropWindow` (`isReleasedWhenClosed = false`);
  - корректный пересчёт масштаба для дисплеев Retina (`backingScaleFactor`), чтобы не терять нативное разрешение и не получать размытые скриншоты;
  - синхронизацию хоткеев: пользовательские настройки не перезаписываются дефолтными при рестарте;
  - защиту от микрокликов при выборе области: минимальный порог drag‑to‑crop — 10×10 точек, плюс уведомление, если область слишком маленькая.
- **Инженерные инварианты и Guard Rails (AGENTS.md):**  
  Все архитектурные соглашения и осознанные WONTFIX‑решения (например, отказ от преждевременной оптимизации попиксельного рендеринга при drag‑to‑crop) зафиксированы в `AGENTS.md`. Каждое изменение проверяется компилятором `xcodebuild`, и мы строго следим за версионированием.

## Тестирование и качество кода

- **Статический анализ и строгая изоляция памяти:**  
  Проект собирается с жёсткой проверкой изоляции конкурентности Swift 6 (`SWIFT_APPROACHABLE_CONCURRENCY = YES`, `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`) — это ловит гонки данных ещё на этапе компиляции.
- **Инспекция системной телеметрии в реальном времени:**  
  Для отладки сервисов и I/O‑операций смотрим логи macOS:
  ```bash
  log show --predicate 'subsystem == "com.simplescreenapp.SimpleScreen"' --debug --last 1h
  ```
- **Сценарный регрессионный чек‑лист:**  
  Надёжность подтверждаем набором интеграционных тестов:
  - симуляция отказа файловой системы: удаляем целевую папку на лету и проверяем, что срабатывает Desktop‑фолбэк;
  - проверка конфликтов хоткеев с системными `⌘⇧3` / `⌘⇧4`;
  - динамическое предоставление и отзыв TCC‑прав Screen Recording;
  - проверка рендеринга и кропа на внешних экранах с дробным и Retina‑масштабированием.
